Build commands, A to Z

This booklet gathers the commands that built the lab, in the order I ran them, from the host to the last service. The jury advised me to bring them together: they let another administrator rebuild the infrastructure without having followed the project. Steps done in a web interface are given as menu paths.

Where to type. Each block names the machine: HV01 (hypervisor terminal), pfSense (web interface or console, option 8), DC (administrator PowerShell, over SSH from HV01), lnx-dc01, TrueNAS (System → Shell), fedora (ssh ais@10.10.10.30), SIEM (ssh ais@10.10.10.40), wg-client (Cockpit serial console).

Three rules kept throughout. A snapshot before every change. No secret in a command or a file: every sensitive input is masked (Read-Host -AsSecureString, interactive prompts). A word in angle brackets (<vm>, <UUID>) is to be replaced.

B · Host HV01: networks and filtering

HV01 — default NAT network (pfSense WAN) and isolated bridge br-tenet (LAN), declared in NetworkManager so they survive any reload (INC-10):

sudo virsh net-start default && sudo virsh net-autostart default

  ipv4.method manual ipv4.addresses 10.10.10.2/24 ipv4.never-default yes ipv6.method disabled

<network><name>tenet</name><forward mode='bridge'/><bridge name='br-tenet'/></network>

C · pfSense (fw01)

HV01 — VM created in Cockpit (two virtio NICs: default then tenet), renamed, media ejected:

sudo virsh shutdown tenet-pfsense

pfSense (console) — menu 1: vtnet0 = WAN (DHCP on the NAT), vtnet1 = LAN; menu 2: LAN 10.10.10.254/24. Then, in the web interface:

  • System → Setup Wizard: name fw01, domain infrasec.lab, NTP, administrator password changed.
  • System → Advanced → Admin Access: HTTPS only (HTTP 80 listener removed, finding F-02).
  • Services → DNS Resolver → Domain Overrides: infrasec.local → 10.10.10.10 (PV-08).
  • VPN → WireGuard → Tunnels → Add: tun_wg0, port 51820, address 10.10.20.1/24.
  • Interfaces → Assignments: tun_wg0 → WG_REMOTE, static IPv4 10.10.20.1/24 (INC-07).
  • VPN → WireGuard → Peers → Add Peer: one public key per device, unique Allowed IPs as /32 (10.10.20.2/32 admin, 10.10.20.3/32 employee, INC-06).
  • Firewall → Rules → WAN: a single rule, UDP 51820. WG_REMOTE: admin → 10.10.10.0/24; employee → 10.10.10.20 TCP 445; everything else denied and logged.
  • Services → SNMP: listening on the LAN, random community; Firewall → Rules → LAN: UDP 161 allowed from 10.10.10.30 only, denied and logged for any other source.
  • Diagnostics → Backup & Restore: encrypted XML export, stored in the host vault.
