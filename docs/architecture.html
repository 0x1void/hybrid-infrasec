2 · Lab architecture

2.1 Overview

The lab runs on a single hypervisor, HV01 (host name TeneT): an ASUS ROG Strix G18 laptop running Fedora 44, with KVM and libvirt, 30 GiB of memory and a 952 GB NVMe disk encrypted with LUKS. The virtual machines share an isolated network, 10.10.10.0/24, carried by the br-tenet bridge, which has no physical card. Only pfSense touches the outside, through the hypervisor's virbr0 NAT network.

The schema below reads in two steps: first the topology, from the access network to the services; then the same lab layer by layer, from the hardware (layer 1) to the applications (layer 7), with for each layer what exists and the security controls in place.

The whole lab takes its time from pfSense, except the SIEM, which follows Canonical's NTP servers and runs its clock in UTC. The Windows domain's DNS is the domain controller; the Samba domain's DNS is lnx-dc01, and resolution between the two domains is in place (PV-08).

Any other inbound flow to the SIEM and to lnx-dc01 is denied by default (F-15, F-25). Every rule was checked from a third machine, never from the target: a test run from the target goes through the loopback and cannot fail.

2.4 Hypervisor capacity

Before adding the Samba controller, I measured memory machine by machine (F-23). The host was using 4 GiB of swap with 29 GiB allocated out of 30. I reduced the two oversized machines based on their real usage; the SIEM, the tightest machine, was left untouched.

2.5 Starting and stopping the lab in the right order

The lab is off at night. Started in the wrong order, it failed silently: the SIEM, faster than Windows, fetched its vulnerability feed before the domain controller's DNS answered (F-14). The lab script now starts the machines in dependency order and waits for a real answer from each service before moving on. To stop, it uses the QEMU guest agent when the machine has one, the ACPI signal otherwise, and never forces anything (F-26). On 26/10, all 7 machines shut down cleanly in 66 seconds, against three refusals from the Windows controller before.
